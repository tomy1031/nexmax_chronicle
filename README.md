# NEXMAX CHRONICLE ― はじまりの未来 ―

> **過去で手を加え、別の時代でその結果を見つけ、NMClawと仲間の知恵で未来の道を自ら開く。**

> **現在の公開版は three.js 版（`web/`）です。** 物語 v7「時を裂く爪」を、はじめにからおわりにまで遊べる形で作っています（下の「物語 v7」）。
> 物語の正は [`docs/物語_v7_時を裂く爪.md`](docs/物語_v7_時を裂く爪.md)、ステージ・ギミック・新しいクローの設計は [`docs/ステージ設計_v1.md`](docs/ステージ設計_v1.md)。
> 操作の仕様は [`NEXMAX_CHRONICLE_新仕様/`](NEXMAX_CHRONICLE_新仕様/)（操作マニュアル v1.1）。物語 v2.3・背骨 v3・プロット v4 は検討の経緯として残しています。
> 以下の説明のうち Godot に関する部分は、旧 Godot 版（ルート直下のファイル、参考として保存）についてのものです。
>
> three.js 版の操作（キーボードのみ）：WASD 移動／↑↓←→ カメラ／Space ジャンプ・ワイヤー離脱／Shift ダッシュ／F 話す／J NMClaw 発射・解除／R 対象切替／Q・E 左右の腕／G 異次元拠点／Tab 装備・記録／Esc 一時停止
>
> スマホ・タブレット（指が主な入力の端末）だけタッチ操作になります（横向きで遊ぶ）：画面の左側をなぞって移動（大きく倒すとダッシュ）／右側をなぞってカメラ／右下の右腕の輪で NMClaw（輪の中に「つかむ」「離す」など）、その左上に「ジャンプ」と、使えるときだけ「話す（調べる・次へ・決定）」「切替」／左上の ❚❚ 一時停止・☰ 装備・記録・手の輪で左腕（一時停止・メニューは画面のタップで戻る）。PC では出ません（確認用に `?touch=1` で表示、`?touch=0` で非表示）
>
> 画質とフレームレート：一時停止（Esc／❚❚）の「設定」タブで、画質（省電力・標準・高画質）とフレームレート（30・60）を選べます（この端末に保存）。スマホ・タブレットは「標準・30」、PC は「高画質・60」から始まります。スマホが熱くなるときは「省電力」と「30」にしてください
>
> 開発：`cd web && npm install && npm run dev`（テスト `npm test`、モデル変換 `npm run models:all`、手順は `web/scripts/README.md`）
>
> タイトル画面：起動するとタイトル（時の輪の中にネクマックス）が出ます。セーブがあれば「つづきから」（最後に記録した時代・場所から再開。その時代の弧が光る）、「はじめから」はセーブを消して最初から（確認あり）。↑↓（W・S）と Enter／F、タップでも選べます。`?stage=` `?continue` `?newgame` などの開発用パラメータがあるときは、いままでどおりタイトルを出さずに始まります
>
> ホーム画面のアプリ（PWA）：スマホで初めて開くと「ホーム画面に追加」の案内が出ます（Android はボタン 1 つ、iPhone は共有ボタン →「ホーム画面に追加」の手順、LINE などの中のブラウザでは「ブラウザで開く」の手順）。「あとで」で閉じると次からは自動で出ず、タイトルの「ホーム画面に追加」から開けます。iPhone は Safari とホーム画面のアプリでセーブが別になるので、先に追加してから遊ぶのがおすすめです
>
> 差分ダウンロード：Service Worker（`web/sw/sw.ts` → 書き出しの `sw.js`）が、ファイルごとに内容のハッシュで管理します。更新のときにダウンロードするのは、中身が変わったファイルのうち、最初に要るものと前に使っていたものだけ（物理・three.js・後処理のライブラリは別ファイルなので、ゲームのコードを直しても落とし直さない）。まだ行っていない時代のファイルは、その時代へ行ったときに初めてダウンロードして残します。新しい版は遊んでいる途中では切り替えず、次に開いたとき（タイトルの前）か、タイトルの「更新する」で切り替えます。仕組みは `web/src/pwa/`・`web/scripts/vite-pwa-plugin.ts`
>
> アプリのアイコン（`web/public/icons/`）はタイトルと同じ 3D のネクマックスから作っています（作り直すとき：`cd web && node scripts/make-icons.mjs`、Chrome が要ります）

## 物語 v7「時を裂く爪」（three.js 版）

2086年、なんばの秋祭り。地下の倉庫で目をさました小さなロボット・ネクマックスは、ソラと祭りを回る約束をする。
その夜、空にひびが入り、黒い手がネクマックスの背中の石（アルン鉱石）をねらう。気がつくと、また同じ朝――。
石の力で「その日の朝」へ戻れるのは 3 回だけ。過去へ行って帰るのにも、光のつぶを 1 つずつ使う（全部で 7 つ）。
NEXTMAKE の観光の看板システム「IDO」で昔の記録を調べ、60年前の大阪・300年前の江戸・900年前のカンボジアへ。
過去で手を加えると、今が変わる。仲間が残してくれたものをつないで、空の怪物オルムをたおし、10月19日の朝を取りもどす。

| 章 | 時代 | 遊びの中身（ボス・ギミック） |
|---|---|---|
| はじめに〜5 | 2086年 ナンバタウン | 祭りの一日・空のひび・同じ朝のくり返し。時計台のぼり、すりぬける怪物から逃げる、ソラに全部話す |
| 6 | 2026年 なんば | よろいの影獣（J でよろいをはがし K で攻撃・つかまった佐伯さんを助ける）、IDO の看板で「時計」「青い」を検索 |
| 7 | 1726年 大坂・仕掛け横丁 | 源兵衛の工房、茶運び人形、夜の時の鐘人形（歯車を止める）、青い刃のかけらで小さな切れ目、ほこらに爪をしまう |
| 8 | 2086年 | 帰るとほこらが消えている（昔が変わると今も変わる）、年代ダイヤルの話 |
| 9 | 2026年 | マツイ社長と約束、ほこらの防衛戦（3 方向の影・江戸の朝を映して照らす） |
| 10 | 2086年 | 360年分の朝日をあびた **時空裂きのNMクロー**（止める・裂く・裏側を切る）、仮面の男トワとの決闘 |
| 11 | 1186年 クメールの都・アルンの寺 | チャンダとおばあさん、三つの塔の鏡、夜の寺の階段の防衛、夜明けの光の扉から裏側へ（オルムのすじを切る） |
| 12〜おわりに | 2086年 | 最後の光のつぶ。ソラといっしょに空を裂き、裏側でオルムの心臓をたおす。10月19日の朝 |

- 新しい力：**時空裂きのNMクロー**（10 章から）。動く物に J で数秒止める／空中のゆらぎに J で裏側への切れ目をひらく／黒い手など裏側にしかない物を J で切る（持つ前はすりぬける）
- 画面左上の 7 つの点が光のつぶ。章のはじめには絵本のとびら（絵・題・一行のあらすじ）が出ます
- 開発用：`?stage=2086|2026|1726|1186&newgame&flags=v7_...`（途中の章から）、`&debug` で `window.__game`（各ステージの `devSkip`）

## 旧 Godot 版（参考）

3つの時代（1726年・2026年・2086年）を行き来する3人称3Dアクションの **序章・縦型試作** です。
2026年の街に置かれたIDO標識を手がかりに過去へ向かい、NMClawで「つかむ・保持する・離す」を使い、
源兵衛やおはるといった仲間と一緒に水門を直す。その結果が2026年の記録と2086年の街の地形に現れます。

## 遊ぶ

**https://tomy1031.github.io/nexmax_chronicle/**

- PCのブラウザで動きます（キーボードとマウスが必要）。スマホではタッチ操作で遊べます（three.js 版）。
- 進行は自動保存され、ブラウザのIndexedDBに残ります（サイトデータを消すとセーブも消えます）。

## 序章に入っているもの

| 順 | 時代・場所 | 内容 |
|---|---|---|
| 1 | 2086年 ナンバタウン | 都市管理AI「ルート」が通路を閉鎖。閉じていく道から脱出する |
| 2 | 2026年 なんば | マツイ社長と出会い、水路沿いのIDO標識を調べて過去への手がかりを得る |
| 3 | 1726年 仕掛け横丁 | 源兵衛・おはると出会い、NMClawで外れた大歯車を戻し、**からくり水門**の協力パズルを解く |
| 4 | 2026年 なんば | 旧水門跡の記録が変わっていることを確かめる（過去の行動の結果） |
| 5 | 異次元拠点 | 回復と最後のチェックポイント。2086年への扉 |
| 6 | 2086年 ナンバタウン | 開いた新しい保守路でソラと会い、警備ロボを停止させる |

タイトルの「クロー練習場（試作）」では、仕様書 §18 の ClawPrototype（歯車をつかんで軸にはめる練習を3回）を単独で遊べます。初めて成功するまでの時間・つかんだ回数・不発の回数を最後に表示します。

水門のパズルは「操作しなければ進まないが、仲間がいないと成功しない」が狙いです。
源兵衛が歯止めを調整する間は歯車を保持し続け、おはるの合図（舟が来ているか）を見て離します。
早く離すと調整が戻り、人がいるときに離すと失敗します。

## 操作

| 操作 | キー・マウス |
|---|---|
| 移動 | `W` `A` `S` `D`（矢印キーも可） |
| 視点 | マウス |
| ジャンプ | `Space` |
| ダッシュ | `Shift` |
| 調べる・話す・IDO | `F` |
| NMClawを構える | 右クリック長押し、または `Q` 長押し |
| つかむ／離す | 構えている間に 左クリック、または `E`（つかんだら、もう一度クリックするまで保持） |
| 攻撃 | 構えていないときに 左クリック |
| 会話を進める | `Space` / `Enter` / `F` / 左クリック |
| ポーズ | `Esc`（`P` も可） |
| 計測表示（FPS・メモリ・フラグ） | `F3` |

ブラウザでは `Esc` でマウスのロックが外れ、ポーズが開きます。

## ローカルで動かす

[Godot 4.7.2](https://godotengine.org/download/) （標準版、.NET不要）を使います。

```bash
# エディタで開く
godot --path . --editor

# そのまま実行
godot --path .
```

初回はエディタで開くか、`godot --headless --path . --import` でインポートしてください。

## テスト

```bash
# ユニットテスト（NMClawの状態機械・水門パズル・TimelineStateのセーブ/ロード）
godot --headless --path . -s res://tests/run_tests.gd

# スモークテスト（全スクリプトの読み込みと各シーンの実行）。最後に "SMOKE OK" が出れば合格
godot --headless --path . res://tests/SmokeTest.tscn

# 1726年の水門パズルを実シーンで通しで動かす（"EDO FLOW OK"）
godot --headless --path . res://tests/EdoFlowTest.tscn

# 物語の各段階で、シーン・スポーン地点・目標の対象がそろっているか（"CONTRACT OK"）
godot --headless --path . res://tests/ChronicleContractTest.tscn

# 描画負荷の計測（ウィンドウあり。各シーンのドローコール数などを表示）
godot --path . res://tests/PerfProbe.tscn -- --shot
```

- ユニットテストは合格で終了コード 0、失敗で 1。各テストに `PASS` / `FAIL` が出ます。
- どちらも出力に `SCRIPT ERROR` が無いことを確認してください（CIでも見ています）。

## デプロイ

`main` へ push すると GitHub Actions（[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml)）が動きます。

1. Godot 4.7.2 とWeb用テンプレート（シングルスレッド版）を取得
2. プロジェクトを取り込み、ユニットテストとスモークテストを実行
3. `godot --headless --path . --export-release "Web" build/web/index.html`
4. GitHub Pages へ公開

リポジトリの Settings → Pages → Source を **GitHub Actions** にしておく必要があります。
手元で書き出すときは、エディタにWeb用の書き出しテンプレートを入れたうえで、上の3のコマンドを実行します。

## 技術メモ

- Godot 4.7.2 / GDScript / **Compatibility** レンダラー（Web書き出し対応。M1 Mac 8GBでの動作を目標）
- Web書き出しは **シングルスレッド版**（`variant/thread_support=false`）。GitHub PagesはCOOP/COEPヘッダーを送れないため
- キャラクター・背景のモデルはすべてコードでプリミティブ（箱・球・円柱など）から組み立てています。外部の3Dモデルやテクスチャ画像は使っていません
- 効果音とBGMはコードで合成しています（外部の音声ファイルなし）
- 状態フラグ（`gate_repaired` / `genbei_drawing_found` / `drawing_confirmed` ほか）は `TimelineState` に集約。
  `future_route_open` は保存せず `drawing_confirmed` から算出します
- 作業の優先順位は、まず「つかむ・離す」の手触り。物理で自由に運ばず、レールや設置位置への補間移動にしています

## ご注意

- これは **企画試作版** です。検証が完了した製品ではなく、仕様も変わります。
- **IDO** と **NMClaw** はゲーム内の独自設定です。実在のIDOに時空移動の機能はありません。
- 1726年にQRコードは存在しません。過去ではネクマックスの装置に記録された帰還先の座標を使います。
- 「アルン鉱石」「オルム」「トワ」「チャンダ」、時空移動のしくみは創作です。1186年のクメールの寺の場面も、史実をもとにした創作です。
- 「仕掛け横丁」「源兵衛」「おはる」「からくり水門」は創作です。
- マツイ社長の氏名・セリフ・容姿は、本人の許諾のもとで使用しています。セリフは実在人物の実際の発言ではありません。
