## 1. プレイヤーに約束する3つの面白さ

### 1.1 発見：「同じ場所なのに、時代が違う」

2026年の古い石段、1726年の職人の工房、2086年の高架道路は**同じ座標に対応する街区**として設計する。過去の行動の結果が、現代の記録と未来の地形に現れる。画面上でも同じランドマークを残し、関係を直感的に伝える。

### 1.2 手応え：「強くつかむより、いつ離すかが重要」

NMClawの気持ちよさは、物を遠くへ投げることだけではない。動く装置を支えている間は安全だが、支え続けると別の経路が塞がることがある。**保持／解除の判断**を遊びにする。失敗しても即座に再試行できる。

### 1.3 共同創造：「一人では作れない未来を、仲間と作る」

源兵衛は機構を発想し、おはるは人の状況と記録の価値に気づき、マツイ社長は技術の目的を選び、ソラは未来側の設備を理解する。**仲間は情報を話す人ではなく、プレイヤーができない工程を担う人**として描く。

### 1.4 採用しない方向性

- NPCのおつかいを完了するだけで時代が変わるゲーム。
- 江戸・現代・未来を背景だけ差し替えた別ステージとして消費するゲーム。
- 何十種類もの武器と素材を先に作り、操作の気持ちよさを後回しにするゲーム。
- 過去の行動で都市全体を即時再生成する、実装規模が際限なく増える設計。
- 既存作品の人物・装置・台詞・象徴的な演出を模倣する設計。

## 2. コアループ：30秒・5分・30分の3段階

### 2.1 30秒単位の基本操作

**周囲を見る → 近づく／跳ぶ → NMClawでつかむ・動かす → 合図や環境を読んで離す → 道が開く／敵に隙ができる。**

移動だけでも楽しいことを前提に、Clawの照準と解除に長い操作を要求しない。成功した時は、機械音・歯車の回転・風や光の変化で手応えを出す。

### 2.2 5分単位のステージループ

**未解決の障害 → 現場の観察 → 時代特有の手掛かり → 仲間と操作 → 成功の即時演出 → 新しいルートと小さな報酬。**

一つの仕掛けに「何をするか」「なぜするか」が見えること。説明文を読む前に、動く物・届かない場所・困っている人を見せる。

### 2.3 25〜40分単位の時代横断ループ

**2026年でIDO標識を見つける → 1726年で原因に介入 → 2026年で資料が変わる → 2086年で新しい道を発見 → 次のIDO手掛かりを得る。**

この一周が「CHRONICLE」の基本構造。1周で開く未来の変化は**大きく見える1件**に絞る。選択肢の増加を地形と行動で表現する。

### 2.4 1周の報酬構造

| 報酬 | 中身 | 見せ方 |
|---|---|---|
| その場の成功 | 歯車が動き、人が通れる | 動く仕掛け＋短い効果音 |
| 過去の結果 | 源兵衛の絵図やおはるの記録 | 短い文字と挿絵。任意で詳細閲覧 |
| 現代の発見 | 史料・地形・マツイ社長の構想メモが更新 | 更新箇所だけを比較表示 |
| 未来の変化 | 閉じていた保守路が開く | 同じカメラ位置から通路が見える |
| 能力の成長 | NMClawの扱いを習得／選べる装備が増える | 実験台で試してから実戦へ |

## 3. 時空移動の仕様：IDOをどう遊びにするか

### 3.1 世界観上の役割

IDOは2026年の街に設置された**歴史・文化の記録へつながるQR案内**。ネクマックスの体内に搭載された架空の時空装置が、情報を手掛かりに特定の場所・時代を定位する。実在サービスとしてのIDOが時空移動を実現する、という主張は行わない。

1726年にQRコードやスマートフォンは置かない。過去への到着後は、ネクマックスの装置に記録された**帰還先の座標**を利用し、指定の安全地点から現代へ戻れる。

### 3.2 プレイヤーの一連の操作

1. 現代ステージで歴史案内の標識を見つける。近づくと反応範囲が柔らかく光る。
2. `F`で調べる。QRそのものを外部カメラで認識するのではなく、ゲーム内の対象オブジェクトを読み取る。
3. 「1726年のこの場所」の短い記録画像が開く。行き先と危険情報を明示。
4. 「時空移動」を選択すると、1〜2秒程度の演出後に過去の対応位置へ移る。
5. 過去では年代・場所・帰還可能地点を常時分かるようにする。序章後半は異次元拠点で未来の座標を復元し、チェックポイントから2086年へ帰還する。

### 3.3 時代移動の制約と拡張

- **初期版**：時空移動はIDO標識と、各時代の安全な帰還地点から実行する。いつでも場所を問わず切り替えられない。
- **中盤の拡張候補**：「時空の窓」。危険のない定点で、同じ位置の別時代の景色を一瞬プレビューし、攻略の手掛かりを見つける。直接の時代移動はしない。
- **後半の拡張候補**：限定された「時間が不安定なエリア」で、2種類の地形を短い間隔で切り替え、ジャンプの経路を作る。これは追加試作で手応えと実装負荷を検証してから採用する。
- **禁止**：すべての時代を常駐読込し、町全体を常時シームレスに変形させること。

### 3.4 結果の伝え方

過去から帰還した直後に、**「変わった事実」を一目で理解できる3秒前後の演出**を入れる。同じ石段、同じ水路、同じ建物の輪郭を画面に残し、更新箇所を自然に目立たせる。変化の理由は会話ではなく「保存された図面→現代の設備→未来の通路」で補足する。

## 4. 時代改変の仕組み：無制限の分岐を作らない

### 4.1 時代をまたぐ因果関係

**過去の行動（原因） → 残されたもの（証拠） → 現代の判断（継承） → 未来の結果（新しい遊び場）。**

「過去で水門を直したから、2086年に空中通路が魔法のように現れる」では説得力が弱い。間に現代の保全記録や、開発に利用された仕組みなど、**納得できる中継点**を置く。

### 4.2 例：旧水路エリア `canal_01`

| 段階 | シーン状態 | ゲーム上の条件 | プレイヤーが見る変化 |
|---|---|---|---|
| A：1726年・介入前 | 水門が故障。人が通れず、歯車が外れかける | `gate_repaired = false` | 押しても動かない装置 |
| B：1726年・介入後 | ネクマックスと源兵衛が水門を安全に修復 | `gate_repaired = true` | 水位が下がり、通路を渡れる |
| C：2026年・史料確認 | 絵図と町の記録が残る。マツイ社長が構想へ反映 | `drawing_confirmed = true` | 展示内容と現代の保守経路が更新 |
| D：2086年・未来の変化 | 未来の保守設備に別経路が見つかり、開く | `drawing_confirmed = true` | 空中通路への入口が解放 |

**整合性の補足**：1726年の一度の修理だけで300年以上後の高架道路が建造された、と説明しない。水路の保存・後世の工事記録・都市設備の改修という中継過程を、短い記録で示す。最初の試作では、変化対象は**一つの短い通路**とする。

### 4.3 状態管理ルール

- 時代ごとに完全な街を複製するが、**同時ロードしない**。各年代は別シーン。
- 変更可能なオブジェクトに`anchor_id`と`variant_id`を設定し、**あらかじめ制作した2状態**を切り替える。
- ストーリーの進行は原則一方向。歴史改変を取り消して分岐を無数に増やす機能は初期版で採用しない。
- ネクマックスの内部記録は変更前の痕跡を保持するが、一般NPCの記憶改変は細かく描かない。
- ロード／セーブ時は状態を再計算せず、保存した進行フラグから再現する。

### 4.4 変化を設計する際のチェック

「原因が分かるか」「変化は遠目でも分かるか」「新しい行動が本当に増えるか」「次に何をしたいかが生まれるか」の4点を満たさなければ、時代改変として採用しない。

## 5. NMClaw：作品の主力アクション

### 5.1 初期能力を四つの動詞に絞る

**つかむ／保持する／移動する／離す。** これをパズル、移動、戦闘で共用する。新しい機能を追加しても、基本操作そのものは変えない。

| 行動 | 使用例 | 面白さの核 |
|---|---|---|
| つかむ | 歯車、木箱、敵の盾、取っ手 | 遠くの対象に干渉できる |
| 保持する | 落下する扉、吊り橋の支え | 他の行動や仲間の作業を可能にする |
| 動かす | 可動式足場、歯車、箱 | ルートや戦闘状況を作り変える |
| 離す | 装置を停止、敵の防御を解除、足場を切り替える | タイミングを選ぶ意味がある |

### 5.2 推奨初期操作（PC・キーボード／マウス）

| 操作 | キー | 説明 |
|---|---|---|
| 移動／視点 | WASD／マウス | 三人称、カメラ方向基準 |
| ジャンプ | Space | 着地直前入力を受け付ける調整あり |
| ダッシュ | Shift | 短距離の高速移動。危険回避にも使う |
| 調べる／話す／IDO | F | 状況に合わせて一つだけ反応対象を表示 |
| NMClaw構え | マウス右ボタンを押し続ける | 近くの対象を自動で補助照準する |
| NMClawつかむ／離す | 構え中にマウス左ボタン | 状況に応じて切替。押し続けを必須にしない |
| 基本攻撃 | 構えていない時のマウス左ボタン | 近距離攻撃。序盤は1種類 |
| メニュー | Esc | 設定・操作・中断 |

操作は試作前の提案。既存P0とキーが競合する場合は**P0の操作感を優先して一括調整**する。ゲームパッド対応は試作後の別工程とする。

### 5.3 Clawの内部状態

`IDLE → AIMING → GRABBING → HOLDING → RELEASING → IDLE`。対象外をつかもうとしても、重い失敗演出はなく、短い不発音と照準フィードバックだけを返す。

初期の対象距離は約5m、範囲外はマークを非表示。可動物は物理計算で無制限に運ばず、**決められたレール・ソケット・補間移動**を優先する。これにより、操作の再現性とM1 Macでの軽量動作を両立する。

### 5.4 NMClawが生むパズルの種類

1. **移動**：離れた取っ手を引いて橋を展開する。
2. **タイミング**：一定時間だけ扉を保持し、味方が通るタイミングで離す。
3. **配置**：歯車を動く台座に固定し、別の装置を動かす。
4. **協力**：ネクマックスが大きな歯車を支え、源兵衛が小さな歯止めを調整する。
5. **戦闘**：敵の盾や足場を動かして、弱点を露出させる。

### 5.5 改良の方向性（能力数を膨らませない）

- 第1段階：**基本Claw**。小物をつかむ／保持／移動／解除。
- 第2段階：**固定Claw**。所定の支点にかけ、一定時間だけ扉や足場を保持。パズル・戦闘双方で利用。
- 第3段階：**牽引Claw**。決められた取っ手へ引き寄せられ、移動範囲が広がる。手触りを別途検証。
- 第4段階：**二点保持**。後半の大規模な仕掛け用。最初から搭載しない。

発展のたびに見た目は少し変わるが、元のネクマックスのかわいらしいシルエットを保持する。

## 6. 仲間の協力：操作で必要性を感じさせる

### 6.1 4人の役割を完全に分ける

| 人物 | 主な役割 | プレイヤーと違う能力 | 操作への落とし込み | 心情の変化 |
|---|---|---|---|---|
| **源兵衛**（1726） | 機械の構造を考案 | 歯車と歯止めの加工・調整 | ネクマックスの保持中に機構を調整 | 一人で完璧に作ろうとする考えを捨てる |
| **おはる**（1726） | 人の安全を確認し記録を残す | 死角からの観察、町の状況把握 | 合図で操作の正しいタイミングを知らせる | 職人の仕事を次代へ伝える |
| **マツイ社長**（2026） | 構想と研究 | 何のための技術か判断し、設計メモを発展 | 過去の資料と未来の記録を比較し、新能力の研究条件を解放 | 完成品の模倣ではなく自分で設計方針を選ぶ |
| **ソラ**（2086） | 設備と制御を解析 | 都市設備の操作、未来技術の分析 | 特定地点で装置を切替、戦闘中に一時的な攻略機会を作る | 安全と自由の両方を守る選択をする |

### 6.2 仲間との協力は3種類

**A：同時協力**（同じ時代の仲間）：Clawで重いものを保持し、その間に仲間が歯車を入れる。成功には両者が必要。仲間は決められた地点へ移動する演出でよく、高度な追従AIは不要。

**B：非同期協力**（異なる時代の仲間）：源兵衛の絵図をおはるが残し、マツイ社長が研究し、ソラが未来でその成果を解析する。本人同士が時代を超えてリアルタイム通話するのではなく、**遺された記録や装置を介する**。

**C：判断の協力**：仲間が「今は離して」と求める理由を、会話だけではなく危険や人の位置で示す。指示通り押すだけでなく、プレイヤーも状況を読んで行動する。

### 6.3 同時協力パズルの最小実装

`プレイヤーが対象を保持 → 仲間が移動開始 → 進捗ゲージ表示 → おはるが人の通過を知らせる → プレイヤーが解除 → 通路が安全に開く`。

同じ操作を3回以上繰り返さない。仲間の作業中に待つだけにならないよう、周囲の足場の回避や反対側の小さな歯車操作など、**短い能動操作**を入れる。ただし初回チュートリアルは一度の正しい判断ができれば成功する。

### 6.4 仲間を「助けられる対象」だけにしない

源兵衛がプレイヤーに新しい考え方を教え、おはるが失敗を指摘し、マツイ社長が選択の責任を引き受け、ソラが自分の過去の判断を見直す。仲間には**プレイヤーを救う瞬間**が必要。主人公だけが正しく、周囲がひたすら感謝する構図を避ける。

## 7. 異次元拠点：休息と試行錯誤の場所

### 7.1 位置づけ

ネクマックスの時空装置に付属する**整備用の異次元空間**。物語上は時間の境界にある小さな保守領域。神秘的だが、何でも解決できる場所にはしない。

### 7.2 拠点の4設備

| 設備 | 機能 | プレイヤーへの価値 | 初期版 |
|---|---|---|---|
| 修理台 | HPを全回復、状態異常を解除 | 次の挑戦へ進みやすい | 必須 |
| 装備ラック | Clawの装備を交換 | 別の攻略方法を試せる | 1つの変更枠から開始 |
| 記録盤 | 江戸の絵図・現代のメモ・未来のログを並べて見る | 因果の理解、次の行き先発見 | 必須 |
| 実験台 | 新しいClawの操作を安全に試す | 説明文でなく体験して理解 | 後続 |

### 7.3 制限と快適さの両立

- 出入りは**安全なチェックポイントのみ**。敵の攻撃中に即時避難できない。
- 拠点から戻ると、基本的には最後のチェックポイントへ復帰。序章で2086年の座標が復元された後は、拠点から未来の安全地点を選んで帰還できる。仕掛けパズルの途中へ自由転移しない。
- 修理台を使えばHP全回復。バランスが崩れる場合は、拠点への帰還で敵が再配置されるなどの調整をするが、初期版では煩雑なペナルティを設けない。
- 装備の素材集めは最初の試作では実装しない。特定の物語イベントで開発メモが更新され、**性能の異なる1〜2種類の装備**を選べる形から始める。
- 異次元拠点は別シーンで、各時代の巨大マップを裏で保持しない。

## 8. 戦闘：Clawを生かした軽快な戦い

### 8.1 基本方針

戦闘は移動・回避・Clawの使い方を確認するために存在する。**敵を倒す速度だけを競うゲームにしない**。最初は未来の小型警備ロボット1種類のみ。江戸時代のからくりは、人命を守りながら停止させる「仕掛け型ボス」にする。

### 8.2 基本のルール

- 初期攻撃は近距離1種類、敵の予備動作を見てダッシュで回避。
- NMClawで敵の盾を一時的に引き、弱点を露出。攻撃できる時間を作る。
- 防御成功の快感は、敵が短くひるむ・機械音が変わる・小さなエネルギーを得るなどの明確な反応で作る。
- 敵ロボットの無力化は破壊表現よりも**機能停止**が中心。過激な描写は不要。

### 8.3 第1章ボス「暴走する舞台からくり」

架空の芝居小屋のからくり舞台が誤作動し、連動する腕や足場が危険な動きを始める。ボスを攻撃して倒すだけではなく、次の順番で制御する。

1. 高低差のある舞台をジャンプで移動し、回転する仕掛けを避ける。
2. NMClawで大型の腕を**一時的に保持**する。
3. 源兵衛が歯止めを調整する。おはるが安全確認の合図を出す。
4. 合図に合わせてNMClawを**離す**と、舞台の危険な連動が止まる。
5. 露出した中央機構へ基本攻撃。これを**変化のある2段階**で完了する。

第1段階は操作習得、第2段階は少し難しい応用。既存の仕掛けで攻略できるため、新武器を大量に作る必要はない。初回は未対応でも安全地帯から再試行できる。

## 11. プレイヤーの成長・報酬・収集要素

### 11.1 成長は「数字が増える」より「できることが増える」

1章ごとに1つの新しいClaw操作、または既存操作の組み合わせを追加する。新しい装備は「前の装備の完全な上位互換」にしない。例：長距離だが保持が短い装備／短距離だが重いものを安定して支えられる装備。

### 11.2 収集物は3種類まで

- **時代の記録**：その場所の過去と未来を理解する。主に物語の報酬。
- **工房の部品**：装備の試作や外見の調整に利用。初期試作では素材の個数管理をしない。
- **記念品**：仲間との関係を表す小物。異次元拠点に飾れる。試作後に検討。

### 11.3 選択肢の扱い

「人を救うか見捨てるか」という過激な善悪分岐は採用しない。**どの方法で仕掛けを解決するか**の小さな選択から始める。重要な物語の結果は共通として、寄り道ルートや報酬、セリフに差分をつける。負担の大きい多分岐ストーリーは後回しにする。

## 12. 画面表示とフィードバック

### 12.1 常時表示するものは最小限

- 左上：HP（ハートや短いゲージ）、現在の時代と場所名（小さく）。
- 中央：Clawを構えた時だけ対象マーク、保持中だけ接続線。
- 右上：次の目標を1行で表示。任意で閉じられる。
- 画面下：直近の操作の一時ヒント。数秒で消える。
- パズル中：仲間の状態を「調整中」「安全確認」「離して！」など短く表示。

### 12.2 成功と失敗の見せ方

- 成功：物理的な手応え（音・振動風演出・機構の動作）＋変わった場所の視覚提示。
- 失敗：なぜ失敗したかを現場で分かるようにする。「保持時間不足」「離すのが早すぎる」など短いメッセージ。
- 時代改変：小さな通知だけで終えず、地形の違いをプレイヤーに見せる。
- 視認性：赤と緑だけで判別させない。形・動き・文字を併用。

## 13. 具体的な試作の完成範囲（Vertical Slice）

### 13.1 一つの街区で完結する試作

**場所**：旧水路を中心とする約60〜90m四方の小エリアを、1726／2026／2086でそれぞれ別シーンとして制作する。数値は概算で、操作感を見て縮小できる。

**最低限の内容**：移動／ジャンプ／ダッシュ、IDO対象1件、源兵衛NPC1人、おはるの合図1件、Claw操作対象2〜3個、水門のパズル1件、図面と現代記録1件、未来の通路変化1件、未来の敵1種類、拠点での回復とセーブ。マツイ社長とソラの会話は短くても必須。

**作らないもの**：フルオープンワールド、現実のQR読取、全時代リアルタイム読み込み、物理計算だけに依存した複雑な装置、NPCの自由な都市生活AI、ボイスのフル実装、大量の衣装・武器・アイテム、時代の多分岐。

### 13.2 P0〜P8の開発順序

| 工程 | 作るもの | 先に確認すること | 合格条件 |

| **P1** | 2026年の小エリア、現代のIDO標識、1726年の小エリア | 移動手順が直感的か | Fでスキャンして別シーンへ移動、帰還できる |

### 13.3 AIコーディング作業の単位

AIには**1回の依頼で1機能＋検証手順**だけを渡す。`AGENTS.md`／`CLAUDE.md`を共通ルールとして使用。各工程で受け入れ基準とテスト操作を明示し、Godotの起動ログと実機動画で確認する。仮モデル・仮音声を使い、ビジュアル制作は操作が成立してから本格化する。

### 14.4 M1／8GB向けの方針

- **Godot 4 Standard／GDScript／Compatibility**。同時にBlenderやブラウザの重いタブを多数開かない。
- 最初は簡易形状を使用し、装飾物よりもカメラ・移動・Clawの応答速度を優先。
- 各時代別シーン。共有マップ全体の同時描画や大規模な動的光源は避ける。
- NPCは定位置・短い経路の演出。大勢の個別ナビゲーションは作らない。
- リアルタイム物理演算はプレイヤーと最小限のオブジェクトに限定。大型からくりはアニメーションや補間移動で制御。
- 初期実行は960×540程度、設計基準1280×720。表示解像度や描画設定を後から選べるようにする。
- 目標は実機30fps以上。FPS平均だけでなく、時代切替・Claw操作直後の停止時間とメモリ使用も記録する。

## 16. 商用作品としての品質基準

1. **遊びと物語を同じテーマへ収束**：序章のClaw操作が、第1章のボス、終章の決断へ発展する。
2. **主導権はプレイヤーにある**：未来の変化が長いムービーで確定するのではなく、プレイヤーの行動と確認によって生じる。
3. **謎には公平な手掛かりがある**：マツイ社長の構想は遭遇前から存在し、源兵衛の設計思想は経路をたどって後世に残る。
4. **世界観を正確に区別**：「仕掛け横丁」「源兵衛」「おはる」「からくり水門」は創作。江戸時代の衣装・街並み・職人文化の考証は別途実施。
5. **会社と商用表現の注意**：IDO・NMClawはゲーム独自の解釈。実在する社長の人物像・氏名・声・肖像は公開前に本人の承諾を得る。ロゴ・音楽・キャラクター・素材の権利処理を行う。
6. **類似性を避ける**：他作品の有名なロボットや発明家の人格・外観・セリフ・展開を再現せず、独自の「設計思想が時代を超えて継承される」構造を育てる。
7. **対象年齢・ユーザビリティ**：読みやすい字幕、再試行の速さ、過度に長い説明を避ける。色以外の形状でも危険や目標を判別できる。
